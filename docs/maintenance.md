# Keeping Scholarmate up to date: the routine

Written 30 October 2026. The aim: any update is a short, known routine with one command to check it. Run everything from `O:\_Chessteaching` with `./tools/.venv/Scripts/python.exe -I ...`.

## The two commands that matter
- `tools/check.py` — everything that must stay true (content validation, skill graph, build, tests including the **route smoke test** that loads every page and the **cross-checks** that every lesson is on the map, in the lists and in a course). `--quick` skips the slow engine validation; `--status` adds the staleness report.
- `tools/status.py` — read-only report of what is stale and the exact command to fix it.

**Rule: after any change, `tools/check.py` must pass before a commit is pushed.** The same checks run on GitHub (`.github/workflows/ci.yml`) so a broken push is visible.

## What to do when...
| You changed or want | Do this |
|---|---|
| A lesson, item, skill or course file | `tools/validate.py <items file>` (engine claims), then `tools/check.py` |
| Added a lesson | it must have a skill with a strand (the cross-check test fails otherwise); add course lessons to `content/courses/*.json` |
| Added a skill node | `tools/check_graph.py --strict`; the map picks it up on its own (`lib/mapLayout.ts`) |
| New game data (monthly) | `tools/refresh_data.py`, then `tools/check.py`, commit, push |
| Added a library book | add its Gutenberg id or candidate row, `tools/fetch_sources.py` or `tools/fetch_archive.py` (the text rights check is mandatory), tag it in `library/tags.json`, `tools/build_library.py` |
| Changed the roadmap | tick the box in `ROADMAP.md`, run `tools/update_roadmap.py` (recomputes percentages and metrics) |
| Changed the name or credit | `app/src/brand.ts` (one edit), plus `NOTICE`, `index.html`, `package.json`; the credit must stay (CLAUDE.md rule 9) |
| Changed the look | colours live in `app/src/theme.css` tokens; layout rules for the Curriculum pages are the `main.curriculum` rules at the end of `index.css` |
| Rebuilt the Windows exe | `powershell -File desktop\build-exe.ps1` (stop the running exe first) |
| Deploying | Vercel builds from the repo with base `/Scholarmate/`; keep the tab icon link root-relative (`/icon.svg`) |

## Things that go stale, and what shows it
- **Shipped content** vs sources: `status.py` compares file dates; `build_content.py` regenerates `app/public/content`.
- **Roadmap numbers**: regenerated by `update_roadmap.py`; never type a count into a doc. Quote counts only from `manifest.json` or the roadmap's computed block.
- **Master statistics**: dated in `stats.json` (`info.built`); the status report warns after 45 days.
- **Library rights**: `check_all.py` re-judges every stored text; a book that fails must be removed or approved by hand on `library/approved.json`.
- **Opening data** (`app/public/openings`): built from Lichess data (see `library/REGISTRY.md`); rebuild only deliberately.
- **Dependencies**: `npm outdated` in `app/` and `pip list --outdated` in the tools venv, quarterly; run `tools/check.py` after each upgrade. Stockfish is vendored by the npm package (`stockfish@19`), upgrade it on purpose and re-validate (engine scores shift).

## Fragile places (learned the hard way)
- Never start the same workflow batch twice (two agents overwrote each other's files).
- `tools/validate_lessons.py` run on a subset overwrites the shared lessons evidence file; run it with no arguments at the end.
- After UI changes load every route (the smoke test does it); a stale dev-server module can show a false error: touch the file or hard refresh.
- In shell scripts on Windows, backslashes and quotes in heredocs get mangled; write files with the editor tools and use `chr(92)` for backslashes in Python one-liners.
- A device's progress lives in the browser's IndexedDB; changing the database schema needs a Dexie version bump and a migration (`app/src/db.ts`).
